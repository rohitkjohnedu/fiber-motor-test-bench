## 1. Overview of Changes

`futek_reader.py` was refactored from a single-sensor GUI into a dual-sensor GUI.
`ForceSensor/futek.py` received several bug fixes related to connection state and DLL thread safety.

---

## 2. `futek_reader.py` — Architecture Refactor

### 2.1 `SensorPanel` class (new)
The monolithic `FutekReaderWindow` was split into a non-widget controller class `SensorPanel` that
owns all state and UI for one sensor. It exposes two composable `QGroupBox` widgets:

- `readout_widget` — outer group box titled "Sensor 1" / "Sensor 2"; contains a top `QHBoxLayout`
  with the Connection group (left) and Force Reading group (right), and the rolling plot below.
- `registers_widget` — device register dump group box for the Raw Data tab.

Each `SensorPanel` has its own `QTimer`, `FutekSensor` instance, `_start_time`, and all UI
elements (`sn_edit`, `force_label`, `plot_curve`, etc.).

### 2.2 `FutekReaderWindow` layout (refactored)
The main window now holds two `SensorPanel` instances and a `QTabWidget` with two tabs:

- **Readout tab** — vertical `QSplitter` with `sensor1.readout_widget` on top and
  `sensor2.readout_widget` below.  Each panel shows `[Connection | Force Reading]` side-by-side
  with the rolling plot spanning the full width below.
- **Raw Data tab** — `sensor1.registers_widget` and `sensor2.registers_widget` side by side.

`pg.setConfigOption("background", "w")` / `"foreground", "k"` moved to `FutekReaderWindow.__init__`
(must precede all `PlotWidget` creation).

`QTabWidget` and `QSplitter` added to imports.

### 2.3 Unit combo moved to the right
The unit selector (`QComboBox`) was originally centred below the force readout in its own row.
It was moved to the right edge of the Force Reading group, vertically centred, so the
cap_min / force_label / cap_max labels have the full available width.
Layout: outer `QHBoxLayout` → left `QVBoxLayout` (readout row + info + tare) + right unit combo.

### 2.4 Font size reduction
Force label and capacity limit labels reduced from `52px` to `28px` to fit two panels on screen.

## 3. `ForceSensor/futek.py` — Bug Fixes

### 3.1 `is_connected` corrupted by second sensor connection (root cause of "first readout stops")
- **Root cause:** `is_connected` read `self.futek_dll.DeviceStatus` and
  `self.futek_dll.DeviceHandle`, which are DLL-global state on the C# `USB_DLL` object.
  When sensor 2 called `Open_Device_Connection`, those properties were overwritten, making
  sensor 1's `is_connected` return `False`.  Sensor 1's `_read_device` thread then entered
  `time.sleep(0.01)` and the Qt timer bailed out, stopping all updates.
- **Fix:** Added `self._connected = False` instance flag.  `is_connected` now returns
  `self._connected`.  Flag is set to `True` inside `connect()` after a successful connection,
  and to `False` at the top of `disconnect()`.

### 3.2 "Impossible to connect" error after 3.1 fix
- **Root cause:** `connect()` used `if not self.is_connected:` to verify the DLL connection
  succeeded, but `is_connected` now returned `self._connected` which was still `False` at that
  point (flag not yet set).  The error message fired for every connection attempt.
- **Fix:** `connect()` now computes `dll_ok` directly from the DLL properties for the
  connection-phase check, then sets `self._connected = True` before calling
  `_get_devices_parameters()`.

### 3.3 `inf` in readout after 3.2 fix
- **Root cause:** `_get_devices_parameters()` starts with `if self.is_connected:`.
  `self._connected` was still `False` when it was called (set to `True` only *after* the call),
  so the method returned immediately without reading `fullscale_value` or `offset`.
  Both stayed at default `0`, giving `0 / (0 - 0) = inf`.
- **Fix:** Moved `self._connected = True` to *before* the `_get_devices_parameters()` call
  in `connect()`.

### 3.4 Erratic readings and stuck graph with both sensors connected
- **Root cause:** The FUTEK USB DLL is not thread-safe for concurrent calls, even from
  separate `USB_DLL()` instances.  Two `_read_device` threads calling `Normal_Data_Request`
  simultaneously (plus register reads during connection) corrupted shared DLL state.
- **Fix:** Added `FutekSensor.dll_lock = RLock()` as a **class-level** lock shared across
  all instances.  Every DLL call is now wrapped with `with FutekSensor.dll_lock:`:
  - `connect()` — `Open_Device_Connection`, `dll_ok` check, `DeviceHandle` read
  - `disconnect()` — `Close_Device_Connection`
  - `get_sensor_load()` — both `Get_Internal_Register` calls
  - `_get_devices_parameters()` — each call in the three while-loop retries, plus the final
    `Get_Firmware_Version` / `Get_Type_of_Board` / `Get_Sensor_Identification_Number` block
  - `_read_device()` — `Normal_Data_Request`
  - `futek_reader.py` `_update_registers()` — both `Get_Internal_Register` calls
    (imports `FutekSensor` as `_FS` and uses `_FS.dll_lock`)
- The lock is acquired only for the DLL call itself (not for surrounding sleeps or
  buffer operations) so the two sensors interleave reads without blocking each other.

### 3.5 Defensive improvement in `_read_device()`
- Added `try/except Exception` around the `Normal_Data_Request` call so a DLL exception
  from a physically disconnected device does not silently crash the polling thread.
  On exception the loop sleeps 10 ms and continues.

## 4. Open Questions / Known Limitations

- **DLL single-device design:** The FUTEK USB DLL appears to have been designed for a
  single device. The class-level lock serialises all calls, which works but halves the
  effective sample rate when both sensors are active.
- **Physical disconnect detection:** With `is_connected` now flag-based, a USB unplug is
  not auto-detected. The `_read_device` thread will keep running but receive non-numeric
  (`"Error"`) readings, which are silently dropped. The user must press Disconnect manually.
- All other limitations from the previous session remain (force value mismatch without
  Tare, LRF400 S/N not readable electronically, `FUTEK_UNITS_CODE` accuracy).
